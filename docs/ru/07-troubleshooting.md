# Диагностика

Реальные проблемы этой установки и то, чем они лечились. Не гипотетические.

**Принцип отладки:** смотреть логи и payload, а не гадать по конфигу.
Почти всё в этом списке выглядело как одно, а оказалось другим.

---

## Детекция «работает», но не находит никого

**Симптом:** Frigate запустился, картинка идёт, ошибок в логах нет,
счётчик детекций стоит на нуле при человеке в кадре.

**Причина:** взяты веса `yolov9-s.pt` вместо `yolov9-s-converted.pt`.
Структура выходного тензора другая, `post_process_yolo` молча возвращает
пустой список.

**Лечение:** пересобрать модель из `-converted.pt` — `models/yolov9/build.sh`
делает это правильно.

---

## Автоматизация не срабатывает, ошибок нет

**Симптом:** человек заходит в зону, событие в MQTT есть, автоматизация
молчит. В трассировке — остановилась на условии.

**Причина:** регистр имени зоны. В конфиге `Exit`, в шаблоне сравнение с
`'exit'`. Jinja регистрозависима.

**Лечение:**

```jinja
{{ 'exit' in trigger.payload_json['after']['entered_zones'] | map('lower') | list }}
```

**Как найти:** подписаться на топик и посмотреть реальный payload:

```bash
mosquitto_sub -h MQTT_HOST -u USER -P PASSWORD -t 'frigate/events' -v
```

## Потерялась вся база лиц

**Симптом:** после `docker compose down && up` распознавание не знает
никого. 500+ обучающих фото исчезли.

**Причина:** отсутствовал том `./media:/media/frigate`. База лиц лежит в
`/media/frigate`, не в `/config`. Без внешнего тома она живёт внутри
контейнера и умирает вместе с ним.

**Лечение:**

```yaml
volumes:
  - ./config:/config
  - ./media:/media/frigate    # ← обязательно
```

Восстановлению не подлежит. Проверьте у себя **до** первого
пересоздания контейнера.

## 502 на auth-сервисе Frigate

**Симптом:** после добавления секции `classification` в конфиг Frigate
начинает отдавать 502 на эндпоинте аутентификации.

**Статус:** ⚠️ **не диагностировано**.

**Обход:** закомментировать блок `classification` целиком и перезапустить
контейнер.

Если вы разобрались — issue приветствуется.

**Причина:** **«Recent Recognitions» — это скрытый dropdown, а не вкладка.**

выглядит так, будто функции просто нет.

## Камера пропала: RTSP отключился сам

**Симптом:** камера EZVIZ была в системе и перестала отдавать поток.

**Причина:** **`Local RTSP` в настройках камеры самопроизвольно
отключается.**

**Лечение:** зайти в приложение и включить обратно. Устойчивого решения
нет — это одна из причин замены EZVIZ на PoE-камеры
([02-hardware.md](02-hardware.md)).

**Проверка потока в обход Frigate:**

```bash
ffprobe -rtsp_transport tcp "rtsp://USER:PASSWORD@CAMERA_IP:554/h264/ch1/main/av_stream"
```

Пароль RTSP у EZVIZ — код верификации **с наклейки на корпусе**, не
пароль от аккаунта в приложении.

## Камера пропала: уехал IP

**Причина:** DHCP выдал другой адрес.

**Лечение:** резервирование по MAC на роутере или статика на камере.
Обязательно для всех камер, без исключений.

## Периодические обрывы сети

**Симптом:** сеть на хосте отваливается на несколько секунд, без
видимой причины, нерегулярно.

**Причина:** Energy-Efficient Ethernet на сетевой карте.

**Лечение:**

```bash
sudo ethtool --set-eee eno2 eee off
```

Чтобы переживало перезагрузку — systemd-юнит в `ops/systemd/`.

## Home Assistant ломает аутентификацию через туннель

**Симптом:** через Cloudflare Tunnel логин не проходит / ошибка о
недоверенном прокси.

**Причина:** не прописан `trusted_proxies`. HA видит все запросы как
приходящие с одного адреса — прокси.

**Лечение:**

```yaml
http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 10.0.0.X    # IP хоста, с которого приходит туннель
```

## Хост уходит в сон при закрытии крышки

**Лечение:**

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

## Хост полностью выключается сам

**Симптом:** машина не спит, а именно **power off**. Нерегулярно, без
закономерности, ничего вменяемого в логах.

**Статус:** ❌ **не решено.**

Известный задокументированный баг (Launchpad), похоже на связку ASUS
BIOS/EC + ядро Linux. Программно не лечится.

**Обход:** переезд на Raspberry Pi 5 как основной хост. Для системы,
которая должна разбудить ночью, «изредка выключается» — дисквалифицирующая
характеристика.

---

## health-check не поднимает VM

**Симптом:** скрипт отрабатывает, но виртуалка с HA не стартует.

**Причина:** скрипт запущен от root. VM VirtualBox принадлежит обычному
пользователю, и `VBoxManage` из-под root её просто не видит.

**Лечение:** cron **обычного пользователя**, не root.
