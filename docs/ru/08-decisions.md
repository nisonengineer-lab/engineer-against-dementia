# Решения и отменённые направления (ADR)

Самый полезный документ в репозитории. Здесь лежат тупики, в которые я
уже зашёл, с причинами — чтобы не заходить в них повторно и чтобы
никто другой не тратил на них время.

---

## ADR-001 · Локально, а не в облаке

**Статус:** принято · неизменно

Речь о видеопотоке из спальни родителей. Отправка его на чужой сервер не
рассматривалась как вариант ни на каком этапе — ни ради удобства, ни
ради экономии на железе.

Побочный эффект оказался экономическим: облачные подписки берут деньги
ежемесячно за обработку, которую железо в доме делает само. Для будущей
бизнес-модели (~250–300 ₪/мес за поддержку) это разница между
перепродажей чужого сервиса и собственным продуктом.

## ADR-002 · Telegram вместо WhatsApp/Twilio

**Статус:** принято · заменило рабочее решение

WhatsApp через Twilio Sandbox **работал**. Отказались по двум причинам:

- сессия Sandbox истекает каждые **72 часа** — систему оповещения нельзя
  строить на канале, который сам себя отключает трижды в неделю;
- переход на production Twilio — дорого при постоянном потоке
  уведомлений.

Telegram Bot API: бесплатно, без сессий, отправка в несколько чатов
одновременно, поддержка фото.

**Грабли:** параметр `target` в сервисе `telegram_bot.send_message`
устарел. Использовать `chat_id`.

## ADR-003 · Улучшение лиц через GPEN/GFPGAN — ОТМЕНЕНО

**Статус:** ❌ отменено окончательно

**Идея:** отдельный RTSP-прокси, который прогоняет поток через
GPEN/GFPGAN, чтобы улучшить качество лиц перед распознаванием.

**Результат:** технически заработало. После долгой борьбы с `CUDA_HOME`,
несовместимыми версиями torch/nccl и настройкой mediamtx — поток шёл,
лица улучшались.

**Почему отменено:** нагрузка на GPU ~92%. Поток рваный. Прямой конфликт
за GPU с самим Frigate, ради которого всё и делалось. Улучшенные лица,
полученные ценой пропущенных детекций — отрицательный размен.

**Вывод:** не форсировать этот путь. Качество распознавания поднимать
дисциплиной обучающей базы и порогами, а не постобработкой потока.

## ADR-004 · YOLOv9-t → YOLOv9-s

**Статус:** внедрено

`yolov9-t` пропускал человека в сложных позах: лёжа на диване, частично
под одеялом, наполовину за мебелью. Для системы наблюдения общего
назначения это мелочь. Здесь это ровно те позы, которые и есть целевое
событие.

**Обязательно:** веса с суффиксом **`-converted.pt`**. Обычные `.pt`
дают другую структуру выходного тензора, `post_process_yolo` во Frigate
возвращает пустой список — **без ошибки в логах**. Система выглядит
работающей и не видит никого.

## ADR-005 · Разделение ответственности между компонентами

**Статус:** принято · определяет всю дальнейшую разработку

Каждый вопрос обрабатывает самый дешёвый компонент, который может:

| Вопрос | Кто | Кто НЕ |
|---|---|---|
| Кто это? | распознавание лиц | ❌ LLM — медленнее и хуже |
| Какая комната? | статичная карта `камера → зона` | ❌ LLM — это константа конфига |
| Он упал? | mmWave / pose estimation | ❌ **LLM — 1–3 с на кадр, недопустимо** |
| Что делает? | vision-LLM | — |
| Обычно ли это? | частотная статистика | ❌ LLM — это арифметика |

Соблазн отдать всё одной большой модели существует и он ошибочный.

## ADR-006 · Pose estimation, а не эвристика по bounding box

**Статус:** спроектировано, не реализовано

Простая эвристика «ширина bbox больше высоты ⇒ человек лежит» ломается
от ракурса камеры: под потолочным углом стоящий человек тоже даёт
широкий bbox.

Решение — YOLOv8n-pose: ключевые точки скелета устойчивы к ракурсу.

## ADR-007 · Object Classification вместо sub_label

**Статус:** сконфигурировано, ⚠️ уперлось в проблему

Идентификация по силуэту и одежде как страховка, когда лица не видно
(Frigate 0.17+, кастомная MobileNetV2).

**`classification_type: attribute`, не `sub_label`** — при типе
`sub_label` результат конфликтует с распознаванием лиц, которое пишет в
то же поле.

**Проблема:** после добавления секции `classification` Frigate стал
отдавать 502 на auth-сервисе. До конца не диагностировано. Секция
оставлена в примере конфига с пометкой; при 502 её надо закомментировать.

## ADR-008 · Withings, а не умные часы

**Статус:** исследовано, не куплено

Критерий один: **давление меряется манжетой**. Всё, что обещает давление
с запястья оптическим методом, для 85-летнего человека с реальными
рисками — не измерительный прибор.

Withings ScanWatch 2 + BPM Connect: официальная интеграция с HA, манжета
с одобрением FDA, разовая покупка.

Отклонены: Omron HeartGuide (снят с производства), Samsung Galaxy Watch
(не настоящее измерение — производитель признаёт), Hilo/Aktiia (дорогая
обязательная подписка + противопоказание >85 лет), Garmin (дорого,
нестабильный неофициальный API). Подробности — [02-hardware.md](02-hardware.md).

## ADR-009 · Голосовое оповещение через Яндекс.Станцию — ЗАБЛОКИРОВАНО

**Статус:** ⏸ приостановлено

Авторизация YandexStation через HACS зависает на подтверждении по QR —
предположительно геоблокировка из Израиля.

Пробовали: бесплатные VPN (Proton, VPN Gate) — стабильно не сработало.
Платный PIA VPN был куплен и установлен, затем **удалён по решению
владельца**: строить постоянный канал оповещения через VPN-костыль —
плохая идея, сначала нужно нормальное решение.

**Открыто.** Альтернативы к оценке: локальный TTS (Piper) через
HA + любая колонка с поддержкой media_player, ESP32-устройство с
динамиком.

## ADR-010 · Клонирование голоса — согласовано, отложено

**Статус:** ⏸ отложено намеренно

Идея: синтез голоса владельца (Coqui XTTS-v2 на машине с GPU) для
диалога с отцом в моменты ночной тревожности. Отец знает об идее, дал
согласие и заинтересован.

**Условие перед внедрением:** консультация с лечащим психиатром именно
насчёт LLM-диалога в ночное время. Технической готовности здесь
недостаточно — вопрос не инженерный.

## ADR-011 · Два тома в docker-compose для Frigate

**Статус:** внедрено после потери данных

```yaml
volumes:
  - ./config:/config
  - ./media:/media/frigate   # ← без этого тома теряется база лиц
```

База обучающих фото лиц лежит в `/media/frigate`, не в `/config`. Без
внешнего тома всё содержимое умирает вместе с контейнером при
`docker compose down/up`.

**Так уже потеряли 500+ обучающих фото.** Строка добавлена не
профилактически.

---

## ADR-012 · Frigate NVR как основа

**Статус:** принято

Альтернативы (Shinobi, Agent DVR, самописный конвейер на OpenCV)
проиграли по одной причине: Frigate из коробки даёт связку
«детекция + зоны + MQTT + запись по событию», и MQTT-интеграция с Home
Assistant — первого класса, а не через прослойку.
