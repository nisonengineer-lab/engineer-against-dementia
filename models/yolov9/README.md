# YOLOv9 → ONNX для Frigate

Детектор человека. Собирается локально, в репозиторий веса не коммитятся.

```bash
./build.sh s 320
```

## Почему `-converted.pt`

В релизах [WongKinYiu/yolov9](https://github.com/WongKinYiu/yolov9/releases/tag/v0.1)
лежат два варианта весов: `yolov9-s.pt` и `yolov9-s-converted.pt`.

Брать нужно **только `-converted`**. Обычные веса дают другую структуру
выходного тензора, и `post_process_yolo` во Frigate возвращает пустой
список детекций. Ошибки в логах при этом **нет** — система выглядит
работающей, но не видит ни одного человека. Диагностируется только тем,
что счётчик детекций стоит на нуле при заведомо непустом кадре.

## Почему `s`, а не `t`

`yolov9-t` пропускал человека в сложных позах: лёжа на диване, частично
под одеялом, наполовину закрыт мебелью. Для этого проекта это не
косметическая проблема — именно эти позы и есть целевое событие
(падение, ночной выход из кровати).

`s` тяжелее по GPU, но на RTX 3050 4GB с двумя камерами по 5–8 fps
запас есть.

## Размер входа

| imgsz | Что даёт | Чем платишь |
|---|---|---|
| 320 | текущий выбор, хватает на дистанции до ~8 м | мелкие/дальние объекты теряются |
| 640 | заметно лучше на дистанции 10–15 м | ~4× нагрузка на GPU |

При переезде на Raspberry Pi 5 + Hailo-8 модель понадобится
перекомпилировать в `.hef` — ONNX там не исполняется напрямую.

## Правка `weights_only`

В Dockerfile есть `sed` по `models/experimental.py`. Начиная с torch 2.6
`torch.load` по умолчанию идёт с `weights_only=True`, а чекпоинты yolov9
содержат pickled-объекты — без правки загрузка падает на этапе экспорта.
