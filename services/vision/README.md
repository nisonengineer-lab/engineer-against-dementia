# Vision-LLM: описание сцены

Инструменты для проверки того, что vision-модель через Ollama способна
описать словами, **что человек делает** — не «кто это» и не «где он».

## Разделение ответственности

Это принципиальная развилка архитектуры, а не деталь реализации:

| Вопрос | Кто отвечает | Почему |
|---|---|---|
| **Кто это?** | Frigate face recognition | Уже есть, работает на порядки быстрее и дешевле |
| **Где он?** | Статичная карта `камера → зона` в `frigate/config.yaml` | Комната не меняется. Просить это у нейросети — тратить ресурс на константу |
| **Что делает?** | Vision-LLM (этот модуль) | Единственное, чего не даёт ни детектор, ни зоны |
| **Он упал?** | ❌ **не** LLM | 1–3+ с на кадр. Для падения это вечность. Нужен pose estimation |

## Требования

- Ollama ≥ 0.12.7 (ниже нет поддержки `qwen3-vl`)
- Модель: `ollama pull qwen3-vl:8b`
- `ffmpeg` + `ffprobe` в системе (для `vlm_video_test.py`)
- `pip install -r requirements.txt`

Ollama живёт **не на хосте с Frigate**, а на отдельной машине с GPU.
Гибридная архитектура: тяжёлые модели остаются на мощном ПК, детекция
и запись — на хосте NVR. Чтобы Ollama слушала сеть:

```bash
OLLAMA_HOST=0.0.0.0:11434
```

и порт 11434 должен быть открыт в файрволе.

## Использование

```bash
# Сервер жив? Модель установлена?
python3 vlm_test.py --check --url http://OLLAMA_HOST_IP:11434

# Логика без сервера — проверка кодирования и сборки запроса
python3 vlm_test.py --selftest
python3 vlm_video_test.py --selftest

# Одно фото
python3 vlm_test.py photo.jpg --url http://OLLAMA_HOST_IP:11434

# Клип: нарезка на кадры -> отправка пачкой как последовательность
python3 vlm_video_test.py clip.mp4 --frames 6 --height 512 --url http://OLLAMA_HOST_IP:11434
```

## Почему видео режется на кадры

Ollama не принимает видеофайл напрямую. `vlm_video_test.py` берёт N
равномерно распределённых кадров через `ffmpeg` и отправляет их пачкой
в поле `images` — модель читает это как последовательность во времени.

Компромисс: больше кадров и выше `--height` = точнее описание, но
картинки быстро съедают контекст. Диагностика в выводе показывает,
сколько токенов ушло на ввод из `num_ctx`.

## Известное поведение qwen3-vl + Ollama

Модель иногда уходит в «размышление» и упирается в лимит генерации до
того, как выдаст ответ — на выходе пустая строка при
`done_reason: "length"`. Поэтому `num_predict` по умолчанию 1024: это
**потолок, а не цель**, он просто не даёт ответу оборваться.

Экспериментальный. Оба скрипта работают как самостоятельные проверки.
Интеграция в поток событий Frigate (`activity_watcher`) — в дорожной
